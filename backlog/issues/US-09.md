### User Story

როგორც **უწყების მენეჯერი**, მსურს ახალი განაცხადის პასუხისმგებელ თანამშრომელზე მინიჭება და სამუშაოს დაწყებამდე საჭიროების შემთხვევაში სხვა თანამშრომელზე გადანაწილება, რათა თითოეულ განაცხადს ჰყავდეს პასუხისმგებელი პირი და მინიჭებების ისტორია შენარჩუნდეს.

### Acceptance Criteria

**Scenario 1**
- **Given** განაცხადი სტატუსით New არის და Manager უფლებამოსილია შესაბამის უწყებაზე
- **When** Manager აირჩევს იმავე უწყების აქტიურ Worker-ს და მიუთითებს ვადას
- **Then** იქმნება Assignment, სტატუსი იცვლება Accepted-ით და StatusHistory აფიქსირებს მოქმედებას

**Scenario 2**
- **Given** განაცხადი Accepted სტატუსშია და სამუშაო ჯერ არ დაწყებულა
- **When** Manager მიუთითებს ახალ აქტიურ Worker-ს და გადანაწილების მიზეზს
- **Then** ძველი Assignment იკეტება EndedAt-ით, იქმნება ახალი Assignment და ისტორია ინახავს ვინ/როდის/რატომ გადაანაწილა

**Scenario 3**
- **Given** განაცხადი InProgress ან Resolved სტატუსშია
- **When** Manager ცდილობს სხვა Worker-ზე გადანაწილებას
- **Then** ოპერაცია უარყოფილია 409 Conflict-ით და არსებული Assignment უცვლელი რჩება

### Planning

- **Role:** უწყების მენეჯერი (დისპეჩერი)
- **MoSCoW:** Must have
- **Story Points:** 3
- **Platform:** web-dashboard, backend-api, database
- **Dependencies:** US-08, US-13

> MVP-ში გადანაწილება შესაძლებელია მხოლოდ Accepted სტატუსში, სამუშაოს დაწყებამდე. InProgress/Resolved დავალების გადანაწილება მომავალი ცვლილების მოთხოვნაა.
