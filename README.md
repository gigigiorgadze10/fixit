# FixIt: კომუნალური პრობლემების შეტყობინების სისტემა

**საგანი:** DevOps And Software Engineering
**დავალება:** პროექტის Backlog-ის შექმნა (ინდივიდუალური)
**ავტორი:** გიგი გიორგაძე

## პროექტის აღწერა

ქალაქში გატეხილი ლამპის, ორმოს ან გადავსებული ნაგვის ურნის შესახებ მოქალაქეს ხშირად არ აქვს მარტივი გზა, რომ ეს მუნიციპალიტეტს შეატყობინოს, ხოლო ზარებით და სოციალური ქსელით შემოსული ინფორმაცია იკარგება და არავინ აკონტროლებს, მოგვარდა თუ არა პრობლემა. **FixIt** არის ვებაპლიკაცია, რომლითაც მოქალაქე ტელეფონიდან, ერთ წუთში აგზავნის შეტყობინებას ფოტოთი და რუკაზე მონიშნული ადგილით. მუნიციპალიტეტის დისპეჩერი შეტყობინებას იღებს, ანაწილებს შესაბამის ბრიგადაზე, ბრიგადა კი სამუშაოს დასრულებას ფოტოთი ადასტურებს. მოქალაქე ყოველ ეტაპზე ხედავს თავისი განაცხადის სტატუსს, ხოლო მერია იღებს გამჭვირვალე სურათს იმის შესახებ, რამდენ ხანში წყდება პრობლემები.

Should have მნიშვნელოვნად აუმჯობესებს გამოცდილებას, მაგრამ მის გარეშეც სისტემა მუშაობს. Could have „სასიამოვნო დამატებებია". Won't have ცნობიერად გადადებულია: ანონიმურობა ზრდის სპამის რისკს, ნატიური აპლიკაცია კი სემესტრის რესურსს აღემატება.

## 5. შეფასება და დიდი story-ების დაშლა

შეფასება გაკეთდა Fibonacci-ის სკალაზე (**1, 2, 3, 5, 8, 13**), ფარდობითი სირთულის მიხედვით. საბაზისო წერტილად აღებულია US-09 (მინიჭება) = **3 ქულა**: ერთი ფორმა, ერთი სტატუსის ცვლილება და ისტორიის ჩანაწერი. დავალება ინდივიდუალურია, ამიტომ Planning Poker-ის ნაცვლად თითოეული story შედარდა საბაზისოს და 8+ ქულიანი სამუშაო განხილულ იქნა დასაშლელად.

**EPIC-1: „მოქალაქეს შეუძლია პრობლემის შეტყობინება და მისი თვალყურის დევნება" (13 ქულა)**

## 6. Definition of Done

Story დასრულებულად ითვლება მხოლოდ მაშინ, როცა **ყველა** პირობა შესრულებულია:

- [ ] Acceptance Criteria-ს ყველა სცენარი შესრულებულია და ხელით შემოწმებულია
- [ ] კოდი ატვირთულია ცალკე branch-ზე და Pull Request გადახედულია (code review) მინიმუმ ერთი ადამიანის მიერ
- [ ] დაწერილია unit ტესტები; ახალი კოდის დაფარვა **≥ 70%**
- [ ] CI pipeline (build, lint, ტესტები) წარმატებით გადის
- [ ] არ არის ცნობილი კრიტიკული ან მაღალი სიმძიმის ხარვეზი
- [ ] შესრულებულია შესაბამისი NFR-ები (მაგ. გვერდი იტვირთება 2 წამში, მუშაობს 360 px ეკრანზე)
- [ ] დოკუმენტაცია განახლებულია (README, API აღწერა)
- [ ] ცვლილება გაშლილია staging გარემოზე და იქ გამართულად მუშაობს
