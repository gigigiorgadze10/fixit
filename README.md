## 1. პროექტის მოკლე აღწერა

ქალაქში დაზიანებული ქუჩის განათების, გზის ორმოს ან გადავსებული ნაგვის ურნის შესახებ მოქალაქეს ხშირად არ აქვს მარტივი და გამჭვირვალე გზა მუნიციპალიტეტისთვის ინფორმაციის მისაწოდებლად. FixIt არის მობილურ ეკრანებზე მორგებული ვებაპლიკაცია, რომლითაც მოქალაქე აგზავნის პრობლემის აღწერას, კატეგორიას, ფოტოსა და რუკაზე მონიშნულ მდებარეობას. მუნიციპალიტეტის დისპეჩერი ამოწმებს განაცხადს და ანაწილებს შესაბამის თანამშრომელზე ან ბრიგადაზე, ხოლო თანამშრომელი სამუშაოს მიმდინარეობასა და დასრულებას სისტემაში აფიქსირებს. მოქალაქე ხედავს საკუთარი განაცხადის სტატუსსა და ცვლილებების ისტორიას, მუნიციპალიტეტი კი იღებს სამუშაო პროცესის ერთიან აღრიცხვას.

## 2. მიზანი და MVP-ის საზღვრები

MVP ფარავს პრობლემის სრულ ძირითად ციკლს:

1. მოქალაქე რეგისტრირდება და შედის სისტემაში;
2. ქმნის პრობლემის განაცხადს კატეგორიით, აღწერით, ფოტოთი და მდებარეობით;
3. მოქალაქე ხედავს საკუთარ განაცხადებსა და მათ სტატუსებს;
4. დისპეჩერი ხედავს შემოსულ განაცხადებს და ანაწილებს თანამშრომელზე;
5. თანამშრომელი ხედავს მისთვის მინიჭებულ ამოცანას, იწყებს სამუშაოს და ამატებს შესრულების ფოტოს;
6. განაცხადი გადადის დასრულებულ სტატუსში და მოქალაქე ხედავს შედეგს.

MVP-ში არ შედის ნატიური Android/iOS აპლიკაცია, ანონიმური შეტყობინება, საჯარო რუკა, მხარდაჭერის ხმები და სტატისტიკური Dashboard. მათი პრიორიტეტები მოცემულია Product Backlog-ში.

## 6. არაფუნქციური მოთხოვნები (NFR)

ქვემოთ მოცემული მოთხოვნები შემოწმებადი სამიზნეებია. შესრულება უნდა გაიზომოს აღწერილ სატესტო გარემოში და არა მხოლოდ ვარაუდით.

| ID | კატეგორია | მოთხოვნა და გაზომვის პირობა |
|---|---|---|
| NFR-01 | Performance | 100 ვირტუალური მომხმარებლის დატვირთვისას ძირითადი API GET მოთხოვნების p95 პასუხის დრო უნდა იყოს **≤ 2 წამი**. გარე რუკის ფილები და ფოტოს ატვირთვის დრო ამ გაზომვაში არ შედის. |
| NFR-02 | Reliability under load | იმავე 100 ვირტუალური მომხმარებლის ტესტში ძირითადი API მოთხოვნების შეცდომების წილი უნდა იყოს **< 1%**. ტესტი ტარდება k6-ით staging გარემოში. |
| NFR-03 | File upload | განაცხადზე დასაშვებია **1–3 ფოტო**, თითოეული მაქსიმუმ **10 MB**. დაშვებული ფორმატებია JPEG და PNG; არასწორი ფორმატი ბრუნდება `415`, ზედმეტი ზომა — `413`. |
| NFR-04 | Responsive UI | ძირითადი მოქალაქის, დისპეჩერისა და თანამშრომლის გვერდები უნდა მუშაობდეს **360 px** და მეტი სიგანის ეკრანზე ჰორიზონტალური გადახვევის გარეშე. |
| NFR-05 | Access control | ყველა დაცული API ოპერაცია ამოწმებს ავტორიზაციასა და როლს; არაავტორიზებული მოთხოვნა აბრუნებს `401`, არასაკმარისი როლის მოთხოვნა — `403`. |
| NFR-06 | Privacy | ყველა ატვირთულ ფოტოზე შენახვამდე უნდა მოიხსნას EXIF მეტამონაცემები; მოქალაქის საკონტაქტო ინფორმაცია არ უნდა მოხვდეს საჯარო რუკის პასუხში ან ჩვეულებრივ აპლიკაციის ლოგში. |

99.9%-იანი ხელმისაწვდომობა და 500 ერთდროული მომხმარებელი შეიძლება განისაზღვროს მომავალი production ვერსიის მიზნებად, მაგრამ ამ სემესტრის MVP-ის შესრულებულ მახასიათებლებად არ უნდა ჩაითვალოს შესაბამისი ინფრასტრუქტურისა და მონიტორინგის გარეშე.

## 7. Definition of Done

User Story დასრულებულად ითვლება, როდესაც:

- [ ] ყველა Acceptance Criteria შესრულებულია;
- [ ] კოდი გადის build-სა და შესაბამის ავტომატურ ტესტებს;
- [ ] ახალი ბიზნესლოგიკისთვის არსებობს unit ან integration ტესტები;
- [ ] არ არის ცნობილი კრიტიკული ან მაღალი სიმძიმის ხარვეზი;
- [ ] ავტორიზაციისა და როლების შეზღუდვები შემოწმებულია;
- [ ] ცვლილება გადახედილია Pull Request-ში (ინდივიდუალური მუშაობისას - ავტორის თვითშემოწმება და საჭიროების შემთხვევაში თანაკურსელის/ლექტორის review);
- [ ] API ან მონაცემთა მოდელის ცვლილებისას განახლებულია შესაბამისი დოკუმენტაცია და EF Core migration;
- [ ] CI შემოწმებები წარმატებით სრულდება;
- [ ] ფუნქციონალი შემოწმებულია staging ან ლოკალურ სატესტო გარემოში;
- [ ] GitHub Issue განახლებულია და მხოლოდ ამის შემდეგ გადადის `Done` სტატუსში.

## 9. არქიტექტურა და ტექნოლოგიები

FixIt იყენებს **Layered Modular Monolith** არქიტექტურას. ერთი ASP.NET Core აპლიკაცია შეიცავს MVC (Razor) UI-სა და JSON REST API-ს; Backend-ის ბიზნესმოდულები ლოგიკურად არის გამოყოფილი, მაგრამ MVP-ში ცალკე მიკროსერვისებად არ იშლება.

| ნაწილი | ტექნოლოგია | როლი |
|---|---|---|
| Backend / Web | ASP.NET Core 10 MVC + API Controllers | გვერდები, REST API და ბიზნესლოგიკა |
| Frontend | Razor Views, Bootstrap 5, მცირე JavaScript | რესპონსიული ინტერფეისი |
| Map | Leaflet + OpenStreetMap | მდებარეობის მონიშვნა და რუკის ჩვენება |
| ORM | Entity Framework Core 10 | მონაცემთა წვდომა და მიგრაციები |
| Database | PostgreSQL | რელაციური მონაცემები და ტრანზაქციები |
