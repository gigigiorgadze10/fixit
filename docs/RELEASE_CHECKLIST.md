# FixIt — Assignment & Architecture Readiness Checklist

## Practical 1 — Product Backlog

- [ ] Project description (3–4 sentences) in README.
- [ ] Stakeholders, payer and veto authority identified.
- [ ] At least 3 system roles described.
- [ ] 8+ User Stories on GitHub Projects (current target: 20).
- [ ] Every Story uses As a / I want / so that.
- [ ] Every Story has Given/When/Then Acceptance Criteria.
- [ ] At least two numeric NFRs (current target: 7).
- [ ] MoSCoW on each Story.
- [ ] Fibonacci points on each Story.
- [ ] Definition of Done documented.
- [ ] MVP scope and total points documented (39 SP).
- [ ] GitHub Projects Board and Table views linked.

## Practical 2 — Architecture

- [ ] Scenario D idea approved by lecturer.
- [ ] Architecture style + 2–3 reasons.
- [ ] Component diagram.
- [ ] Backend design pattern.
- [ ] Frontend design pattern (Mobile and Web).
- [ ] 5+ API endpoints (current contract has substantially more).
- [ ] SQL/NoSQL choice and DB schema/ERD.
- [ ] Technology stack and rationale.
- [ ] At least 2–3 risks and mitigations.

## Consistency checks

- [ ] README, Architecture, API, Data Model and Backlog use same roles/statuses.
- [ ] US-18 is Must Have and included in MVP.
- [ ] Push notifications are explicitly outside MVP.
- [ ] US-16 is rating only; US-20 is reopen request.
- [ ] US-09 reassignment rule matches API and DB constraints.
- [ ] `Resolved` requires a completion photo.
- [ ] Storage/DB process does not claim a cross-system ACID transaction.
- [ ] Bearer token is not described as JWT unless a real JWT/OIDC provider is implemented.
